Choose the operation your script needs

Use wb-python inside the Sandbox to read a known Workbench request from a research script, retrieve a completed response for review, or submit new authorized work to a selected Thread. A separate client process can reopen an exact request without keeping the original Python process running.

Task Entry Requirement
Prepare and validate request text build_request or wb-python validate A reviewed local wb-python installation
Read an existing request ProfileAccess, ReceiptLog and Workbench Operator-selected Profile, Thread, socket and existing SDK receipt
Submit new work once Explicit SDK or CLI submission Actual task authorization, a permitted other Thread and a private receipt directory
Use the restricted Client API in the Sandbox Independent wb-client with LocalTransport An existing operator policy and admitted scope
Plan Host-side readback Independent wb-client with a reviewed fixed-command transport A reviewed Host copy and an approved, verified deployment

The current adapter admits native Codex versions 0.171.0 and 0.172.0. See validation scope for the operations actually checked. wb-python 0.2.0 requires ordinary Python on POSIX. The core package uses the standard library, and a source build uses setuptools. A notebook and the independent Client are optional.

Prepare the Sandbox Python environment

Start in a writable directory inside the Sandbox with Python 3.11 or later and venv and pip available. Obtain the complete reviewed wb-python source or wheel from the operator. Keep the package and your actual work data in locations already approved for the environment. This collection contains the manual and its references. A separately supplied runtime provides the commands below.

read -r -p 'Reviewed wb-python source directory or wheel: ' WB_PYTHON_SOURCE
WB_ENV="$(mktemp -d)/wb-python-env"
python3 -m venv "$WB_ENV"
"$WB_ENV/bin/python" -m pip install "$WB_PYTHON_SOURCE"
"$WB_ENV/bin/wb-python" --help

The command lists supported CLI operations. For an offline input check, supply only an ordinary text request and a short explicit context list.

printf '%s\n' '{"message":"Propose a label for a synthetic concentration profile.","context":["Horizontal axis is position. Vertical axis is concentration."]}' |
  "$WB_ENV/bin/wb-python" validate

The result carries schema wb.python.v1 with your selected text. This step does not connect to a Profile or submit a request. A JSON error means the input needs correction. API reference describes byte bounds and accepted fields.

Select the existing Profile and Thread

Use a trusted operator's existing configuration. A Session Profile identifies the persistent grouping, and the native Thread ID identifies one conversation. A native session_id distinguishes a tree that can contain multiple Threads. A Turn ID identifies one execution within a Thread. The SDK receipt refers to a selected native request within those identities.

Value Meaning
Workspace The canonical configured Workbench workspace root
Profile helper and SHA-256 Path to the installed Session Protocols helper and its reviewed expected hash
Native socket The existing private socket in the Sandbox
Session Profile and Thread The confirmed Profile name and exact Thread ID admitted for this task
SDK receipt directory and hash The private directory used by the submitting SDK and the original 64-character content hash

The read-only workflow needs a known Thread and its SDK receipt. The operator provides the workspace, helper pin and socket. Obtain those values in the same Bash session as the installation.

"$WB_ENV/bin/wb-python" --workspace "$WB_WORKSPACE" --helper "$WB_HELPER" \

The profile list reads the installed registry. An empty list or a mismatched binding means the selection needs reconciliation with its owner. For a confirmed selection, the recovery subcommand with --profile and --thread asks the existing helper for that Profile's recovery. Keep its recovery output within the configured workspace.

Read back a saved request without submitting work

Use the exact original receipt. The following script keeps the connection read-only, verifies the receipt against the selected Session reference and reports whether terminal messages are available.

export WB_WORKSPACE WB_HELPER WB_HELPER_SHA256 WB_SOCKET WB_PROFILE WB_THREAD
export WB_RECEIPTS WB_RECEIPT
"$WB_ENV/bin/python" - <<'PY'
import json
import os

from wb_python import ProfileAccess, ReceiptLog, Workbench, WorkbenchError

env = os.environ
try:
    profiles = ProfileAccess(env["WB_WORKSPACE"], env["WB_HELPER"],
                             env["WB_HELPER_SHA256"])
    receipt = ReceiptLog(env["WB_RECEIPTS"]).read(env["WB_RECEIPT"])
    thread = env["WB_THREAD"]
    with Workbench(profiles, env["WB_SOCKET"], allowed_threads=(thread,),
                   enabled_operations=("read",)) as workbench:
        selected = workbench.attach(env["WB_PROFILE"], thread, resume=False)
        if receipt.session != selected:
            raise SystemExit("Receipt belongs to a different Session reference.")
        snapshot = workbench.status(receipt)
        summary = {"state": snapshot["state"]}
        if snapshot["state"] == "completed":
            result = workbench.result(receipt)
            summary.update(message_count=len(result["messages"]),
                           code_execution=result["code_execution"])
        print(json.dumps(summary))
except WorkbenchError as error:
    raise SystemExit(error.code) from None
PY

A completed request with one response reports {"state": "completed", "message_count": 1, "code_execution": "inert_text_only"}. Your script can read the message text from result["messages"]. You control where that content goes. For queued, inProgress or unresolved, preserve the original receipt and read again later. A failed or interrupted request is terminal, and requires interpreting the existing outcome before further work. The connection closes when the context block exits.

Submit one authorized request and retain the acknowledgement

Use this workflow only with actual task authorization, a permitted other Thread, an existing private SDK receipt directory, and the installed helper and socket from the earlier steps. Use the caller's true identity. The example can request same-ID resume when admitted, which an unloaded Thread may need before submission. A busy Thread requires reconciliation before a new submission.

read -r -p 'Actual caller Thread ID: ' WB_CALLER_THREAD
read -r -p 'Approved request text: ' WB_MESSAGE
"$WB_ENV/bin/wb-python" --workspace "$WB_WORKSPACE" --helper "$WB_HELPER" \
  --helper-sha256 "$WB_HELPER_SHA256" --socket "$WB_SOCKET" \
  --profile "$WB_PROFILE" --thread "$WB_THREAD" \
  --caller-thread "$WB_CALLER_THREAD" --receipts "$WB_RECEIPTS" \
  --enable resume --enable submit submit --resume --message="$WB_MESSAGE"

Submission sends the explicit text into the selected native runtime. The native queue may start an acknowledged input automatically. Keep the returned receipt, queue_receipt and native reference in the same private workflow. To read the exact request again in a fresh process, use the readback example with that receipt in WB_RECEIPT. Status can lag acknowledgement briefly. Check again with the same reference if the Turn has yet to be correlated. An unknown acknowledgement calls for reconciliation, since submitting again could duplicate an accepted input.

Use a configured Agent Profile from an application

The authorized local Python bridge can create a child Thread using an existing Agent Profile. An Agent Profile supplies a reusable role definition and invocation lifecycle, separate from the Session Profile. The actual parent Thread must already hold the confirmed Session Profile selection.

The operator supplies the installed bootstrap package, existing configuration, reviewed source-pin mapping, private output and receipt roots, the exact existing Agent Profile name, parent Thread ID, and approved task text. Use the existing helper to list or inspect the intended role. In the local application, construct ExistingBootstrap(installed_package, existing_config, source_pins, output_root), pass it as bootstrap to Workbench with ("read", "create") enabled and the actual caller ID and private ReceiptLog, then call create_session(session_profile, agent_profile, task).

The installed flow allocates the invocation, forwards the genuine parent selection after its gate, and returns the validated child Session reference. Keep bootstrap.last_invocation for evidence, readback and lifecycle handoff. The calling workflow saves the outcome and closes or parks the invocation with the installed helper. An explicitly authorized later submission can require same-ID resume as described in the previous section. A partial failure can leave invocation records to reconcile. The bootstrap contract describes the local operator interface. The restricted endpoint has no remote Session creation operation.

Read catalog metadata and inspect returned content

Local scripts may select named template metadata with TemplateCatalog(exact_catalog, allowed_ids=(...)). Supply the canonical catalog file and the exact IDs you need. list() reads selected entries, and get(id) returns a selected entry. An empty allowlist returns an empty tuple. The package reads only the catalog. A catalog result describes an entry and its rights status, and grants no import or execution authority.

A terminal Workbench.result() returns agent-message text, native state, and optional operator-registered artifact descriptors. Read an artifact by its exact registered ID through Workbench.artifact() within the selected Turn. The returned code and bytes require separate handling from a result read. The optional Client can parse a whole wb.generated-result.v1 JSON proposal with parse_generated_result(text). It retains code as text and keeps reported validation distinct from independent verification. A missing, malformed or ambiguous generated response requires inspecting the original retained result.

Read a restricted Client handle inside the Sandbox

Use the optional independent wb-client with LocalTransport if the original request came through the restricted Client API. In the same virtual environment, install the reviewed Client source or wheel supplied by the operator. Obtain the existing policy for the same deployment principal and the original request_handle from the acknowledgement. It differs from a direct SDK receipt hash.

read -r -p 'Reviewed wb-client source directory or wheel: ' WB_CLIENT_SOURCE
"$WB_ENV/bin/python" -m pip install "$WB_CLIENT_SOURCE"
read -r -p 'Existing trusted policy path: ' WB_POLICY
read -r -p 'Original Client request handle: ' WB_HANDLE
export WB_POLICY WB_HANDLE
"$WB_ENV/bin/python" - <<'PY'
import os

from wb_client import Client
from wb_python import LocalTransport
from wb_python.endpoint import OperatorPolicy

policy = OperatorPolicy.load(os.environ["WB_POLICY"])
with Client(LocalTransport(policy)) as client:
    request = client.request(os.environ["WB_HANDLE"])
    snapshot = request.status()
    print(snapshot["state"])
    if snapshot["state"] == "completed":
        result = request.result()
        print(len(result["messages"]), result["code_execution"])
PY

The fixed policy must admit the selected handle and the status operation. The second read requires request.result admission. If the handle is unknown to that principal or the policy changed, confirm the original handle and current scope with the operator. This workflow closes only its Client connection. It makes the same policy checks in process as the restricted endpoint.

Keep the Sandbox, Host and notebook paths distinct

Use direct Workbench with the trusted helper and socket inside the Sandbox. Use the restricted Client API with LocalTransport when the caller needs its fixed policy, operation scope and principal. The Client can list admitted Profiles and Sessions through that policy. Select an exact pair, and keep the returned request_handle if work is authorized.

Host Python uses a separately reviewed independent wb-client copy and the fixed-command transport described in the restricted endpoint guide. The published validation evidence does not establish deployed Host SSH or Host-to-Sandbox isolation. Refer to the deployment operator for the approved transport and review of that Host artifact. Access through a local Unix socket is an existing Sandbox pathway.

The optional wb-jupyter package provides IPython commands as a separate consumer of the Client. Its Sandbox mode can use LocalTransport. A Kernel can display a returned code proposal for review. Integrating and executing a cell are separate actions with separate authorization.

Recover from a refused or uncertain operation

Observation Next action
Empty Profile or Session selection Ask the operator which existing identities are admitted for the task.
Mismatched Thread, binding, or receipt Verify the exact reference and selected Profile with the operator.
queued, inProgress or unresolved Retain the receipt and use later readback.
waitingOnApproval or waitingOnUserInput Use the existing native review or input mechanism.
Busy Thread or self-call refusal Reconcile the current work and admitted other Thread.
Unknown acknowledgement or failed receipt write Preserve the known native IDs and evidence. Check the original operation before sending anything again.
Result output deferred Keep the same reference and seek the complete native result.
Unsupported runtime or operation Check the supported edition and operator's actual policy.

A timeout ends the caller's wait. Keep the original receipt or handle. The SDK reports the native state and observed notification metadata without an invented completion percentage. A terminal output does not certify scientific correctness.
