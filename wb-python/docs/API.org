* Identities and deterministic operations
=resolve_session_reference(profile, thread_id, workspace, binding, recovery,
native)= is pure. It joins authoritative selected Profile binding/recovery with
actual native Thread.id/sessionId/cwd, refuses mismatch and returns immutable
=SessionReference=. Thread.id identifies one conversation; sessionId may be shared
by a native tree. The dictionaries must come from trusted configured adapters;
structural agreement does not authenticate arbitrary caller-supplied data.

=build_request({message, optional context, optional schema})= returns immutable
=RequestSpec=. Message and at most 8 context fragments are explicit UTF8 text,
bounded together to 64 KiB. Unknown fields, nonfinite JSON and nontext context fail.
No function inspects files, variables, environments, notebooks or interpreter
state to assemble context. Text/code is never evaluated or used as an import/path.

* Profile adapter
=ProfileAccess(workspace, helper_path, helper_sha256)= loads the explicitly pinned
installed Session Protocols helper. =list()= reads its registry projection;
=binding(thread_id)= delegates confirmed-binding resolution;
=recovery(profile, thread_id)= checks selection before helper startup. Existing
registry/bindings/owner/receipt authority is preserved. Public errors are sanitized
=WorkbenchError= objects with =code/message/acceptance_unknown=.

* Existing native connection and requests
=Workbench(profiles, socket_path, allowed_threads=..., caller_thread=...,
enabled_operations=("read",), receipt_log=...)= connects only to an existing
private same-user Unix socket. Exactly native 0.171.0 and 0.172.0 versions are
admitted during experimental API initialization; patch/prerelease/future/unknown
versions refuse. The initial 0.172 observation covers the four selected read
method shapes only, not a full schema or write compatibility. Actual scoped
resume/queue/result/continuity evidence remains separately version-pinned.
The adapter advertises application clientInfo version 0.2.0. No daemon is launched or configured.
Operator operation/Thread subsets restrict access; they confer no underlying wb
approval. Mutations require explicit caller identity and a private ReceiptLog.

| Method | Observable behavior |
|--------+---------------------|
| profiles_available() | Existing helper's Profile registry mapping. |
| attach(profile, thread_id, resume=False) | Selected confirmed Profile + exact native ID/cwd; no automatic new Session. |
| attach(..., resume=True) | Existing native resume on idle/unloaded other Thread; no permission/model/config overrides. |
| submit(session, request_mapping) | Validate selected content, refuse busy/self/foreign Thread, queue/add once; return acknowledged queue/correlation/request-hash ref. |
| start(reference) | Return a uniquely correlated existing native Turn without mutation; otherwise start the exact still-pending queue only on an idle other Thread. |
| status(reference) | Native queue or exact Turn snapshot; no percentages; missing queue-to-Turn mapping is unresolved. |
| events(reference) | Explicit snapshot plus filtered observed notification metadata; no replay promise. |
| result(reference) | Terminal native Turn status and agent-message text only; reasoning/raw tool bodies omitted. |
| wait(reference, timeout=..., interval=...) | Bounded convenience; timeout neither cancels nor resubmits. Caller/self waiting refuses. |
| artifact(reference, registered_id) | Optional operator-registered exact native Turn/item artifact with bounded bytes/hash/owned-path checks. |
| create_session(profile, agent_profile, task) | Optional existing bootstrap bridge; real AI/native work only under actual caller authorization. |

=RequestReference= retains SessionReference, queue_id, client_message_id,
request_sha256, optional turn_id and optional observed correlation_item_id.
RPC IDs, request hashes and receipt hashes
are correlation/evidence identifiers, not native acceptance, idempotency or
human-request R-ID. =ReceiptLog= stores append-only content-hashed references in
an explicit private directory; the native queue/history remain state authority.
Save/reload via =record(ref)= and =read(content_hash)=. There is no automatic
retry, latest-Turn guess, queue daemon or mirrored state database.
Native queue/add may auto-consume/start an accepted input. For an original
queue-only reference, the API scans the selected Thread's cross-Turn item pages
once (at most 20 pages of 100 items each) for the exact native userMessage.clientId.
Only one matching native Turn is accepted; conflicting queued/history or multiple
Turn matches refuse. An incomplete bounded scan reports its bound, not uniqueness.
Recovered reference/observed item ID is appended to the configured ReceiptLog;
the original receipt is preserved. status/events/result/wait/artifact all consume
that same recovered reference, including from another client/process. Missing
correlation remains unresolved. This is not an idempotency or retry guarantee.
Snapshots preserve native =thread_status= and =active_flags=, including
=waitingOnApproval= and =waitingOnUserInput=, without approving either request.
LocalTransport serializes its own endpoint exchanges. Client/Workbench/native
objects provide no general thread-safety guarantee; independent clients use
separate connections and the same acknowledged native references.
After disconnect the daemon may unload an idle Thread. Read-only history may
still resolve results; a followup explicitly resumes the same ID with
=attach(..., resume=True)= instead of creating a new worker or assuming an earlier
process's attachment remains loaded. No automatic daemon/start is introduced.
An acknowledged queue item may have a short unresolved queue/history visibility
gap. wait keeps polling read-only until the same deadline; it does not send the
request/start again, cancel work or guess an uncorrelated Turn. Missing correlation
at the deadline remains a wait timeout with the original reference retained.

* Reusing the installed source-free bootstrap
:PROPERTIES:
:CUSTOM_ID: wbpy-api-bootstrap
:END:
=ExistingBootstrap(installed_package, existing_config, source_pins, output_root)=
uses fixed installed =ad_native.allocate/bootstrap= with pinned peer modules.
This trusted local operator configuration is not a remote/request field.
The existing config supplies lifecycle helper/source pins, policy paths,
existing CLI/edition, exclusions and resource/timeout policy. This application
does not construct alternative approval/model/sandbox settings.

Before allocation the adapter checks the actual parent binding/recovery. It
copies the genuine parent confirmation, allocates an existing AgentProfile's
immutable snapshot, runs the installed source-free bootstrap gate, waits for
that owned process to exit, then lets the installed helper forward selection,
bind/startup and associate the actual child runtime. The project task text is
recorded for attribution; it is not sent as bootstrap source content.

=Workbench.create_session= adds the actual returned child ID to its derived local
scope and returns a validated SessionReference. The child may be notLoaded after
CLI exit; explicitly call =attach(profile, child_id, resume=True)= before submit.
=bootstrap.last_invocation= retains the actual helper instance association for
caller handoff. The caller owns saving outcome and setting IDLE/DONE through the
existing AgentProfile helper when its work ends. Bootstrap failure retains its
real receipt/invocation for reconciliation and is never silently retried.
No synthetic choice/default Profile or second manager is introduced.
See the [[file:./READER_GUIDE.org::#wbpy-application-extension][application workflow]] for explicit selection of both profiles.

* CLI
=wb-python validate= validates JSON from stdin without a workspace. =profiles=
and =recovery= use explicit =--workspace --helper --helper-sha256=.
Native operations additionally require =--socket --profile --thread=; mutations
need =--caller-thread --receipts --enable OP=. =submit --message TEXT= optionally
accepts repeated =--context TEXT= and =--start=. =start/status/events/result=
take =--receipt HASH=. Returned JSON is data; no artifact/code execution command
or arbitrary raw RPC, filesystem, Python or shell option exists.
The separate =wb-python-endpoint --policy TRUSTED_PATH= implements the closed
versioned stdio subset in [[file:REMOTE.org][REMOTE.org]]. It is not SSH authentication or
an unrestricted remote form of this local Python API.

* In-process restricted transport (0.2)
:PROPERTIES:
:CUSTOM_ID: wbpy-api-local
:END:
=LocalTransport(policy)= accepts the existing trusted
=wb_python.endpoint.OperatorPolicy=. Its =exchange(bytes) -> bytes= reuses
Endpoint.handle and bounded wire encoding; =close()= and context management own
only that endpoint's native connection. An owned lock prevents overlapping
exchanges/close on this transport. Close is idempotent; later calls refuse.
No process/listener is started. Policy, scope, receipt and native authorities
are identical to the endpoint, including unsupported creation/approval/cancel.

The optional independently installed =wb_client.Client= can consume this adapter:

#+begin_example
import os

from wb_client import Client
from wb_python import LocalTransport
from wb_python.endpoint import OperatorPolicy

policy = OperatorPolicy.load(os.environ["WB_POLICY"])
client = Client(LocalTransport(policy))
# Explicitly select a permitted Profile and exact existing Thread using Client.
client.close()  # Releases this connection, never accepted native work.
#+end_example

The core preset uses only the standard library. The integration example uses
the optional independent Client and an operator-provided =WB_POLICY= path.
No implicit resume, new Session or background task manager is introduced.
The source distribution's =examples/local_client.py= requires a real trusted policy; it lists permitted
Profile names only and is not run automatically.

* Selected template metadata (0.2)
:PROPERTIES:
:CUSTOM_ID: wbpy-api-templates
:END:
=TemplateCatalog(exact_catalog, allowed_ids=())= accepts one canonical absolute
existing =wb.templates.catalog.v1= file and at most 32 explicit template IDs.
=list()= returns a tuple of selected metadata dictionaries; =get(id)= returns
one admitted entry. Empty admission returns an empty tuple without payload I/O;
unselected get refuses before reading. Missing admitted IDs refuse.

Only the catalog is read, bounded to 262,144 bytes and 128 entries. Duplicate JSON
fields/IDs, nonfinite JSON, traversal/excluded routes and symlink file/parent
routes refuse. Child directories/entries are never probed. Returned fields are
=id,path,entry= and declared =python_import,version,status,redistribution=.
Other child-specific metadata is not projected. Paths and import names are inert
metadata; this API neither copies/imports/executes templates nor grants rights.
No registry is created. Host Client catalog discovery remains unsupported.
The source distribution's =examples/selected_templates.py= requires the exact catalog and explicit --allow.
