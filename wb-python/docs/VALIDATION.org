* Native evidence and deployment limits
A selected Sandbox integration exercised ordinary Python Client and
LocalTransport submission into native 0.172, exit of the submitting process
and result readback from a fresh process. Later selected notebook requests
used the same existing Thread in the Sandbox. These observations concern
their selected operations and tested editions. Adapter version admission
describes the editions the code can recognize. A specific operation's
compatibility depends on corresponding native evidence.

For the direct SDK, the documented receipt-readback procedure was checked
with its actual SDK classes and synthetic Profile and native peers. The
fixtures exercised a completed request, a request in progress and a
mismatched receipt. They observed no native mutations or receipt writes.

A real Host SSH deployment still needs evidence for authentication,
fixed endpoint and policy selection, Host source trust, account restrictions
and isolation. A receipt identifies acknowledged native work. It does not
guarantee exactly-once execution, automatic resumption or recovery from a
service failure. Returned text is an Agent result. Scientific validation
requires a separate check.
