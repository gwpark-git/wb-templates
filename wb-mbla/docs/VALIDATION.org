* What is established
The C++17/GSL template runs independently of the originating workspace. Under a declared common no-contraction floating-point policy, the copied original and modern implementation produce identical printed output for the checked non-cake, mild-cake and demanding-cake cases. Independent arithmetic/linear checks and invalid-input boundaries pass. This establishes bounded engineering preservation, not complete physical validation or historical reproduction.

The researcher's prior Python/C++ non-cake agreement is established reported evidence. Its exact historical source/inputs/tolerance were not recovered in this task. The source README's uncertainty about its copied history remains. No new failed check retroactively invalidates the researcher's prior work. Python has no cake extension; no cake symmetry/parity is asserted.

* Reproduce the standard checks
Run the README CMake/CTest commands. tests/regression.py uses only Python's standard library and bounded subprocesses, with all files under its --work directory. Fixtures in tests/fixtures are immutable: the runner never regenerates them. SOURCE_MANIFEST.json identifies copied inputs; FIXTURES.json identifies current fixture inputs, original-source generator and FP policy.

The standard suite checks:
- MATRIX deep/self assignment and bounds; a separately specified 2x2 LU solve.
- Exact Carnahan–Starling Z(0.2)=2.40625 and dimensional Pi=0.240625 for kT/Va=1/2.
- Dilute transport limits and hydraulic series resistance at Rcake/Rmem=0 and 3.
- Closed-form zero-osmotic axial pressure, both Dirichlet boundaries and
  second-order 25→49-node errors: 0.00223494→0.000558750 Pa.
- Frozen original-source non-cake, mild-cake and active demanding-cake outputs.
- Missing, duplicate, mistyped, nonfinite, invalid-domain and undersized inputs;
  missing table/output parent, malformed continuation and unsorted property table.
- Exit 3 on iteration exhaustion; accepted whitespace/comments; exact CT unity
  table/analytic equivalence; six/four-column detailed-output schema.
- Independent reconstruction of printed Darcy–Starling velocity and CSV export.

Regression allowance is abs(error)<=1e-12+2e-6*abs(reference), based on the inherited six-decimal scientific printer and two last-digit rounding units. All three executed GCC release cases were exactly equal as printed. This is a new regression allowance, not the unrecovered historical Python/C++ tolerance. A denominator-sign mutation 1/(1+Rcake/Rmem)→1/(1-Rcake/Rmem) was compiled in an isolated copy; the unit test failed at the independent series-resistance expectation. Frozen data were not changed to make a test pass.

* FP policy is part of source/environment identity
The original Makefile used machine-specific Homebrew paths and did not declare floating-point contraction policy. On the checked Linux AArch64 GCC 14.2.0 / GSL 2.8 environment, adding only matrix bounds checks changed a demanding-cake run's branch/stop history: reported zero-based index 93→36, with max absolute differences 0.035163203 in wall concentration, 5.59734e-7 m/s in permeate velocity, 1.3455e-4 m/s in axial factor, and 1.39785 in Rcake/Rmem. The original default output is retained separately as cake.dat. Neither -O2 nor -O3 alone resolved it.

With -ffp-contract=off applied to both original and modern source, their printed results match exactly, including inherited stopping index 92. Standard GCC/Clang CMake builds now declare that policy. This is a new common numerical policy; it does NOT reproduce the original default-FMA output. The controlled result supports contraction/inlining sensitivity; the exact changed machine instruction was not audited. A target compiler/library needs its own active-cake reference comparison. Do not weaken a regression tolerance after such a mismatch.

Known inherited numerical/semantic limits remain explicit:
- The pressure outlet row retains an osmotic forcing contribution, causing
  a small endpoint mismatch (about +0.1 Pa after printing in the non-cake case).
- Inlet axial velocity uses a first-order forward pressure difference; the
  outlet uses a second-order backward stencil. Concentration can amplify a
  small inlet-factor error.
- Cake search thresholds, safety substitutions and stopping flags can give a
  stopping message despite large flux drift; default-FMA sensitivity is material.
- phi_cake input is ignored in favor of 0.64; cake thickness accounting is a
  separate optional source rule. No constitutive coefficient was silently fixed.
- The main cake column and outlet sidecar have inherited mixed normalization.

* Fresh optional Python comparison: failed at its new allowance
The optional tool tools/compare_python.py takes an explicitly supplied reviewed public mBLA scripts directory. It records seven module hashes, imports only named numerical modules with bytecode writes disabled, and needs NumPy/SciPy. Do not import an unreviewed checkout. It is not part of standard CTest.

A fresh v3.1 comparison used pressure inlet, R=0.5 mm, L=0.5 m, Lp=6.7e-10 m/(Pa s), eta0=1e-3 Pa s, T=293.15 K, a=a_H=10 nm, phi_feed=0.001, DLP=130 Pa, Pout=101325 Pa, linear HP TMP parameter 1 kPa, SPHS diffusion/viscosity, CS osmotic pressure and 25x120 nodes. kT used the same GSL constant; Python uses integral axial pressure, C++ finite differences. Python relaxed increments converged below 1e-6 with no cap in 128 iterations. The new allowance was <1% maximum relative difference in wall concentration, permeate velocity and axial factor. * Feedback corrections and fast boundary/grid checks
Two demonstrated engineering defects were corrected separately from the scientific method. A successfully opened main or sidecar stream can fail during writing, flushing or closing; each output now reports that error before successful execution is announced. The POSIX boundary test induces EFBIG after successful open using a 1024-byte RLIMIT_FSIZE and a deliberately preserved ignored SIGXFSZ disposition. It covers result.dat, .Rout and .Fval independently, first checking each corresponding unrestricted baseline. Platforms without that POSIX facility report NOT_RUN for this boundary; they do not acquire a passed late-write claim.

The same boundary oracle rejects the pre-fix implementation, whose truncated primary and both sidecars returned success. A second contract checks N_iter decimal 2400, scientific 2.4e3 and hexadecimal 0x960: all accepted spellings now consume 2400 and produce the same printed table. Before the correction, the latter spellings passed validation and consumed 2/0 through atoi. No fixture, numeric tolerance, physical law or ordinary-input behavior was changed.

The unit pressure oracle now also checks a prescribed uniform cake coefficient Ln=1/4 under pressure/pressure boundaries and a clean velocity/pressure boundary. Each uses an independently specified zero-osmotic exact solution at 25/49 uniformly spaced axial nodes with identical endpoints; the observed error must fall by approximately four when h halves. These are quick pressure-grid sensitivity checks. They are not nonlinear cake or transverse-grid validation. The [[file:FIXED_POINT_METHOD.org][method owner]] explains the researcher's non-monotonic applicability limit and distinguishes observed safeguard activity from a hypothesized cause of floating-point sensitivity.
