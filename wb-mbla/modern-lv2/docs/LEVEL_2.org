* Scope
Level 2 refactors the case driver and the fixed-point wall/cake update
inside the existing architecture. A case still proceeds through input
validation, parameter and workspace initialization, the axial hydraulic
solve, transverse computations and the iteration/analysis outputs.
Only the driver and the two operations below change inside the
production computation. The pressure stencil, LU interface, transverse
marching and quadratures, transport closure equations, owned storage,
and final analysis remain in their inherited modules.

The warning exit returns the prior trial. Level 1 wrote a backup value to
a separate trial variable immediately before breaking. That value never
reached the return expression. The removed search counters and previous
onset minimum likewise did not feed the calculation. No threshold was tuned
to obtain agreement.

* Unchanged operations used by the active path
- =file_IO= parses and validates scalar and literal path settings.
  =parameters= defines the inlet pressure convention and dimensional scales.
- =dispersion_properties= dispatches transport and osmotic laws and owns the
  property tables. =matrix= supplies owned row-major storage and the GSL LU
  interface. =AUX_MATRIX= owns work arrays for the outer step and local profiles.
- =gen_yt_arr= makes the dimensionless transverse grid. The hydraulic functions
  build permeability, solve axial pressure, and derive axial and wall velocity.
- =get_phi_yt_div_phib_with_given_phiw= performs the transverse march.
  =get_Ieta_yt= and =get_ID_yt= integrate viscosity and inverse diffusion.
  =get_F1=, =get_F2= and =get_F_modi= evaluate the existing flux functional.
- =process_at_z_modi= evaluates the candidate from the unchanged integrals.
  =fprint_analysis_with_fouling= recomputes the output from the final wall and
  resistance. The [[file:SCIENTIFIC_GUIDE.org][scientific guide]] defines its units.

* Source comments and optional Python search
Local comments identify units, state, update ordering and branch purpose
where those facts affect interpretation. The commented C++ release build
matched the replayed executable bytes before CTest was run again.
The [[file:PYTHON_CAKE.org][optional Python cake kernel]] reproduces the inner search on captured
C++ inputs through the standard library or a compiled backend.

* Re-run local checks
Use the Make or CMake quickstart for the four CTest entries. The optional
paired trace takes explicit Level 1 source plus the two strict-FP release
executables built from their respective sources. Run from this Level 2 folder.

#+begin_src sh
python3 tests/compare_paths.py \
  --baseline /path/to/modern-lv1 \
  --baseline-exe /path/to/lv1/build/mbla \
  --candidate-exe /path/to/lv2/build/mbla \
  --work /new/path/to/mbla-paired-trace
#+end_src

The harness instruments disposable source copies. It compares ordinary and
traced outputs and diagnostics before comparing the original and refactored
traces. It compares each saved state and hydraulic array by a digest over the
stored double values. Per-station lines carry raw and relaxed wall values and
the two branch decisions. Each cake-search digest covers its trial resistance,
step, normalized residual and active branch sequence. A final trace per
iteration records the updated wall, resistance, integrals, radial concentration,
shear fields and stopping state. The compact fixtures cover no cake, mild
cake and demanding cake. The demanding case is a numerical regression fixture.

* Publication-derived benchmark
The separate matched TMP benchmark uses eight archive/replay cases on 200 × 400
grids, including CASE2 b = 1. The local package needs only its included small
fixtures. Actual private archive inputs, outputs and execution receipts remain
with the originating study. See [[file:VALIDATION.org][the validation rules]]
and [[file:../provenance/PACKAGE_CHECKS.json][the edition receipt]] for the
performed scope. Mesh convergence and entrance matching require their own
evidence.
