* Second-order pressure FDM and inlet axial velocity reconstruction
The axial pressure equation uses second-order finite differences in both
editions. With prescribed inlet pressure, the default
=inlet_velocity_order=2= uses a three-point forward difference to
reconstruct the inlet axial velocity factor. The
pressure boundary rows and interior/outlet velocity formulas retain their
existing discretizations. Prescribed inlet velocity uses the imposed value.

The manufactured cubic tests the velocity stencil at 25 and 49 axial nodes.
The clean pressure-driven solve gives observed inlet axial velocity orders
of 1.970 and 1.985 across 25, 49 and 97 axial nodes. In the 1 kPa non-cake comparison
against the separate semi-analytic Python solver, the maximum full-axis
wall-concentration difference on the common radial grid decreased
from 10.4522% to 0.06007%. Both radial-grid choices meet the selected 1%
allowance for the three compared observables with the corrected stencil.

At 5 kPa the 25 × 120 pressure-inlet input exhausts 2,400 iterations.
The included [[file:../examples/pressure-inlet.inp][49 × 240 input]] meets the
same stopping tolerances, with zero particle-flux drift at printed precision.
The 20 kPa coarse diagnostic stops with 31.34% peak drift and first positive
cake resistance at z/L = 0.125. The revised inlet axial velocity
reconstruction is verified for the stated tests and conditions.

* Reproduce the standard checks
Use the CMake/CTest commands in [[file:../README.md][the package README]].
The suite covers independent component checks and CLI behavior. It uses
separate run directories and leaves the frozen fixtures untouched.

| CTest entry | Tested behavior |
|-------------+-----------------|
| =mbla_units= | Matrix ownership and bounds, independent LU solve, Carnahan–Starling pressure, dilute transport and hydraulic series resistance. Closed-form axial pressure with pressure/pressure and velocity/pressure boundaries, including prescribed uniform permeability. A manufactured cubic checks the current and legacy velocity stencils, and the velocity inlet uses its imposed value exactly. |
| =mbla_regression= | Compares all ten printed columns of three 25 × 120 pressure-inlet fixtures with =inlet_velocity_order=1=. Also checks CT table/analytic equivalence, detailed output and whitespace on the current default, plus invalid input and iteration-limit status. | =mbla_input_contract= and =mbla_output_contract= | Exercise input/continuation and batch output contracts. Late write failures are exercised where POSIX supports the required resource limit. |

The printed-table allowance is =1e-12 + 2e-6 * abs(reference)=
for the absolute error in each stored value. It reflects the six places
after the decimal point in the inherited scientific printer. All three
legacy replays were equal at stored precision on the checked strict-FP GCC
build. The allowance belongs to these fixtures. The historical
researcher-reported Python/C++ agreement used an unrecovered comparison
setup. The retained [[file:../provenance/FIXTURES.json][fixture manifest]]
identifies inputs, source and generator settings.

An isolated denominator-sign mutation in the hydraulic series law failed
the independent resistance test. These checks support selected component,
interface and regression claims. The closed-form pressure check uses
zero osmotic forcing and prescribed permeability and measures the axial
discretization in that controlled problem.

* FP policy is part of source/environment identity
The original Makefile used machine-specific Homebrew paths and did not declare floating-point contraction policy. On the checked Linux AArch64 GCC 14.2.0 / GSL 2.8 environment, adding only matrix bounds checks changed a demanding-cake run's branch/stop history: reported zero-based index 93→36, with max absolute differences 0.035163203 in wall concentration, 5.59734e-7 m/s in permeate velocity, 1.3455e-4 m/s in axial factor, and 1.39785 in Rcake/Rmem. The original default output is retained separately as cake.dat. Neither -O2 nor -O3 alone resolved it.

In the historical comparison, applying =-ffp-contract=off= to both
builds gave identical printed results with first-order inlet axial velocity
reconstruction, including stopping index 92 for the demanding case. The maintained GCC/Clang
builds use this strict-FP policy and reproduce those selected outputs
when =inlet_velocity_order=1= selects that reconstruction. The original
default-FMA output has a different branch history. The experiments did not trace the first
changed machine instruction.

** Historical demanding-cake grid audit
The historical =examples/cake.inp= with =inlet_velocity_order=1= reproduces
=cake-strict.dat= byte for byte on Linux aarch64, GCC 14.2.0 and GSL 2.8 with contraction disabled.
At stopping index 92 the normalized wall-update RMS was zero and the
relative outlet-resistance update was 9.52562e-6. Both input tolerances are
1e-5. The largest axial deviation in the printed particle-flux column is
+23.51797% relative to the inlet. It occurs at the first interior axial node,
upstream of the first positive cake resistance at node 4. The outlet deviation
is +0.01177%.

Temporary field tracing reproduced the same output and showed negative radial
volume fractions upstream of cake, reaching −2.219 at the inlet and −2.369
at the first interior node. With the 25×120 grid, tightening both tolerances
to 1e-7 left a +23.14028% peak deviation. Holding the original tolerances and
using 480 or 960 radial nodes at the same 25 axial locations removed negative
values from the traced final radial profiles and reduced the peak absolute
deviation to 0.01094% and 0.00988%, respectively. A separate uninstrumented
25×480 run reproduced the diagnostic build's output byte for byte. Tightening
both tolerances on that grid further reduced the deviation to 0.0000937%.

These historical runs show strong sensitivity of the flux deviation
to radial resolution at the tested axial grid. The original fixture remains a coarse source regression. At
480 radial nodes, changing the axial grid from 25 to 49 to 97 nodes moved
the mean permeate velocity from 3.813755 to 3.628970 to 3.529956 µm/s.
The change in mean permeate velocity shows axial-grid sensitivity. The
upstream cake onset places these cases outside the admitted physical
comparison. Entrance matching remains a separate model requirement.

* Inherited numerical and I/O limits
- The pressure outlet row retains an osmotic forcing contribution, causing
  a small endpoint mismatch (about +0.1 Pa after printing in the non-cake case).
- Cake search thresholds, safety substitutions and stopping flags can give a
  stopping message despite large flux drift; default-FMA sensitivity is material.
- phi_cake input is ignored in favor of 0.64; cake thickness accounting is a
  separate optional source rule. No constitutive coefficient was silently fixed.
- The main cake column and outlet sidecar have inherited mixed normalization.

* Reproduce the controlled C++–Python comparison
The optional tool tools/compare_python.py takes an explicitly supplied reviewed public mBLA scripts directory. It records seven module hashes, imports only named numerical modules with bytecode writes disabled, and needs NumPy/SciPy. Do not import an unreviewed checkout. It is not part of standard CTest.

Use =--radial-grid cpp-log --inlet-velocity-order 2= with the
maintained executable for the matched-grid result. Repeat in a separate
run directory with =--inlet-velocity-order 1= for the historical inlet
axial velocity reconstruction. The
common-grid legacy run exits 1 because its wall-concentration error
exceeds the allowance. The native-grid option is =--radial-grid native=.

The pre-correction v3.1 comparison used pressure inlet, R=0.5 mm, L=0.5 m, Lp=6.7e-10 m/(Pa s), eta0=1e-3 Pa s, T=293.15 K, a=a_H=10 nm, phi_feed=0.001, DLP=130 Pa, Pout=101325 Pa, linear HP TMP parameter 1 kPa, SPHS diffusion/viscosity, CS osmotic pressure and 25x120 nodes. kT used the same GSL constant; Python uses integral axial pressure, C++ finite differences. Python relaxed increments converged below 1e-6 with no cap in 128 iterations. The selected allowance was <1% maximum relative difference in wall concentration, permeate velocity and axial factor. The old wall-concentration comparison exceeded it.

* Feedback corrections and fast boundary/grid checks
Two demonstrated engineering defects were corrected separately from the scientific method. A successfully opened main or sidecar stream can fail during writing, flushing or closing; each output now reports that error before successful execution is announced. The POSIX boundary test induces EFBIG after successful open using a 1024-byte RLIMIT_FSIZE and a deliberately preserved ignored SIGXFSZ disposition. It covers result.dat, .Rout and .Fval independently, first checking each corresponding unrestricted baseline. Platforms without that POSIX facility report NOT_RUN for this boundary; they do not acquire a passed late-write claim.

The same boundary oracle rejects the pre-fix implementation, whose truncated primary and both sidecars returned success. A second contract checks N_iter decimal 2400, scientific 2.4e3 and hexadecimal 0x960: all accepted spellings now consume 2400 and produce the same printed table. Before the correction, the latter spellings passed validation and consumed 2/0 through atoi. No fixture, numeric tolerance, physical law or ordinary-input behavior was changed.

The unit pressure oracle also checks a prescribed uniform cake coefficient Ln=1/4 under pressure/pressure boundaries and a clean velocity/pressure boundary. Each uses an independently specified zero-osmotic exact solution at 25/49 uniformly spaced axial nodes with identical endpoints; the observed error must fall by approximately four when h halves. These are quick pressure-grid sensitivity checks. They are not nonlinear cake or transverse-grid validation. The [[file:FIXED_POINT_METHOD.org][method owner]] explains the researcher's non-monotonic applicability limit and distinguishes observed safeguard activity from a hypothesized cause of floating-point sensitivity.
